d. core business logic (flows)
    1. synchronous intake (post orders)
        1. receive validated payload and generate uuid
        2. insert order into db with ACCEPTED status
        3. publish message to order.fulfilment.queue
        4. return 202 accepted to client immediately
    2. status polling (get orders)
        1. retrieve current order and line-item status from db
    3. asynchronous fulfilment consumer
        1. listen to order.fulfilment.queue
        2. check idempotency (prevent duplicate processing via processed_messages table)
        3. execute conditional inventory decrement
        4. apply backorder logic if stock is insufficient
        5. generate invoice plaintext document using dataweave
        6. write temporary, final, and archived files to local system
        7. update order status to FULFILLED or BACKORDERED
        8. publish routing payload to order.notify.queue
        9. route failures to DLQ on error
    4. asynchronous notification consumer
        1. listen to order.notify.queue
        2. read generated invoice file from local path
        3. compile email body using dataweave
        4. send email with .txt attachment via smtp
        5. update db notified_at timestamp
